# 완료 기준

이 네 가지는 한 항목도 빠뜨리지 마세요.

• 목표
누가 어떤 문제를 겪나요?
어떤 결과가 필요하나요?

• 완료 상태
무엇이 만들어지면 끝인가요?
사용자가 무엇을 할 수 있나요?

• 완료 확인 기준
무엇을 실행하고 어떻게 확인하나요?
기대하는 결과는 무엇인가요?

• 제약
지켜야 할 조건은 무엇인가요?
하지 않을 일은 무엇인가요?

하단에는:

네 항목은 우리 팀의 실제 내용으로 채워주세요.
화면 적고 빈칸을 남기지는 마세요. 앞뒤 내용이 서로 충돌하지 않는지도 확인합니다.


# 문제 정의

문제정의란, **고객/사용자의 관점에서 우리가 해결해야 할 핵심 문제를 명확하게 정의하는 것입니다. 
처음 보이는 현상만 문제라고 단정하기보다 누가 어떤 상황에서 어떤 어려움을 겪고 있는지, 왜 그런 어려움이 발생하는지를 구체적으로 살펴보는 것이 중요합니다.** 
특히 공급자의 관점에서 “무엇을 만들어야 할까?”를 먼저 생각하기보다, 고객/사용자의 경험과 맥락에서 문제를 바라보는 것이 좋은 문제정의의 출발점입니다.  

**아래 4가지 질문을 활용해서 문제정의를 해보세요.** 

| **Who** | 누구의 문제인가요? | “이 문제를 실제로 겪고 있는 고객/사용자는 누구인가요?” |
| --- | --- | --- |
| **When**  | 언제, 어떤 상황에서 발생하나요?  | “고객/사용자는 언제, 어떤 상황에서 이 문제를 경험하나요?”  |
| **What** | 어떤 어려움을 겪고 있나요?  | “그 상황에서 고객/사용자가 느끼는 어려움/문제는 무엇인가요?”  |
| **Why** | 왜 이런 어려움이 발생하나요?  | “이 문제가 발생하는 원인/이유’는 무엇인가요?”  |

4가지 질문을 확인했다면, 다음과 같이 **문제정의문**으로 정리해볼 수 있습니다. 
⇒ **(고객/사용자)는 (~상황에서) (어려움)을 겪고 있다. 왜냐하면, (원인/이유)이기 때문이다.**
