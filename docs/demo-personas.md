# 네 명의 데모 구매자

사용자가 제공한 `demo-persona-purchases.json`의 구매 관계를 `src/data/demo-personas.json`에 정리했다. 가상 고객 4명, 각 10개 구매 항목이며 중복을 제외한 실상품은 33개다. 이름과 상품 선택은 시연용 설정이고 실제 고객·주문 정보가 아니다.

| 구매자 ID | 이름 | 초기 캐릭터 | 테마 |
| --- | --- | --- | --- |
| demo-f01 | 민서 | f01 | 밝은 홈카페 |
| demo-f02 | 지우 | f02 | 식물과 홈쿠킹 |
| demo-m01 | 도윤 | m01 | 차분한 독서 공간 |
| demo-m02 | 준호 | m02 | 편안한 작업실 |

각 구매자는 패션 3개, 식품 3개, 리빙 2개, 뷰티 2개를 보유한다. 첫 방문은 민서이며 메인과 각 카테고리의 ‘체험할 공간’에서 다른 이름을 선택하고 ‘이 공간 보기’를 누르면 전환한다. 캐릭터 외형 변경은 구매자 변경과 별개다.

## 데이터와 상태

- 구매자의 상품 ID와 구매 이벤트 ID만 소유 관계를 결정한다. 이름·현재 가격·카테고리는 상품 DB에서 읽고 에셋은 API에서 상품 ID로 연결한다.
- 제공 파일의 이미지 경로·frame·과거 검증 결과를 런타임의 권위 있는 정보로 사용하지 않는다. 실시간 매핑이 없으면 기본 예시 그림을 유지한다.
- 구매일은 제공되지 않아 ‘데모 구매’로 표시한다. 식품의 초기 3회는 포장 수량이 아닌 데모 사용 횟수다.
- 모든 구매 의류는 진열 상태로 시작하며 캐릭터는 기본 옷으로 시작한다. 기존 착장 기능은 공간용 스타일 예시이며 실제 상품 피팅을 재현하지 않는다.
- 머그·조화는 테이블, 베개는 침대, 조명은 형태에 맞는 위치를 사용한다. 카테고리의 구매 목록과 순서는 공간 배치에 의해 바뀌지 않는다.

`gscene-persona` 쿠키는 허용된 네 가상 ID 중 하나만 저장하며 로그인·인증 기능이 아니다. 잘못된 값은 기본 구매자로 돌아간다. 착장, 잔량, 찜, 장바구니와 생활 상태는 `user.id`별로 나눈 로컬 저장소에 저장하며 전환 후 복원한다. 초기화는 현재 구매자에게만 적용한다.

## 연결과 검증

기존 공유 상품 DB와 에셋 API 연결 방법은 [에셋 연결·인수인계](design/backend/ASSET_HANDOFF.md)를 따른다. 실제 주소·비밀번호는 별도로 전달한다. 기존 `db:seed`는 이 33개 상품을 갖춘 데이터가 아니므로 데모 연결을 위해 실행하지 않는다.

`tests/demo-personas.test.mjs`는 구매자별 정확한 ID 집합, DB에서 가져온 상품 정보, 준비된 에셋, 카테고리 일치, 잘못된 쿠키 및 미연결 처리를 검사한다. `tests/demo-state.test.mjs`는 구매자별 상태 분리와 현재 구매자 초기화를, `tests/persona-geometry.test.mjs`는 새 상품 형태와 팬트리 배치를 검사한다. 세 검사는 전체 `npm test`에 포함된다.
