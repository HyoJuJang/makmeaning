## STEP 1 — Observe

### 탐색 범위와 근거

GS SHOP 모바일 웹을 비로그인 상태, 390×844 뷰포트에서 실제 조작했다. 모바일 네이티브 앱이나 실제 휴대폰 성능을 측정한 것은 아니다.

실행 흐름: 홈 → 카테고리 → 주방용품 → 검색 진입 → ‘자취 냄비’ 검색 → 테팔 냄비 상세 → 상품문의 → 필수정보 → 리뷰 → 홈에서 확인했던 견과 상품 상세 → 리뷰 → 구매하기의 수량·총금액 팝업.

결제, 장바구니 등록, 회원가입, 문의 작성, 외부 전송은 수행하지 않았다. ‘구매 고민’은 실제 고객 관찰이 아니라 이 흐름을 통한 전문가 점검이며, 리뷰·문의만 기존 고객이 남긴 행동 근거다. 리뷰 작성자의 연령은 알 수 없다. 초기 결과와 베스트순으로 노출된 일부 리뷰를 읽었으며 전체 리뷰의 빈도를 추정하지 않았다. 이미지 상세 전체나 방송 영상의 내용을 모두 검토하지 않았다.

근거 페이지:

- S1 [모바일 홈](https://m.gsshop.com/index.gs)
- S2 [카테고리](https://m.gsshop.com/m/sect/category.gs?mseq=441439) → 추천 영역의 주방용품으로 이동
- S3 [‘자취 냄비’ 검색 결과](https://m.gsshop.com/search/searchSect.gs?tq=%EC%9E%90%EC%B7%A8%20%EB%83%84%EB%B9%84&mseq=401172)
- S4 [테팔 일리코 16cm 냄비](https://m.gsshop.com/prd/prd.gs?prdid=1032098388) — 상품문의·필수정보·리뷰 탭 직접 클릭
- S5 [하루견과 리치넛 100봉](https://m.gsshop.com/prd/prd.gs?prdid=1080130093) — 리뷰·구매 팝업 직접 확인
- S6 [같은 이름의 60봉 구성](https://m.gsshop.com/prd/prd.gs?prdid=1080558547) — 홈의 상품 카드만 확인, 상세 미탐색

가격·리뷰 수·노출 순서·방송 상태는 관찰 시점 값이며 바뀔 수 있다. 두 구성의 원재료·포장·적용 혜택까지 동일하다고 검증한 것은 아니다.

### 첫 해석을 수정한 지점

‘상품과 정보가 많다’만으로 고객 문제를 확정하지 않는다. 필터, 속성별 리뷰, 관련 구성, 배송 날짜, 공유가 이미 있다. 더 많은 추천이나 리뷰 요약을 추가하는 것은 충분한 차별화가 아니다. 실제로 남는 과업은 **내 상황을 조건으로 바꾸기, 확인하지 못한 사실을 찾기, 내 소비속도에 맞게 수량을 고르기**다.

### 강한 문제 4개 선정 — 아직 최종 후보는 선정하지 않음

문서에 지정된 네 관점(실제 행동 가능성, 시간·노력·불확실성, UI보다 깊은 문제, GS가 풀 이유)으로 정성 비교했다. 점수처럼 보이는 가상의 고객 데이터는 만들지 않았다.

보류 이유: P01은 이탈·관심 근거가 약하고 기존 선행 가설에 끌릴 위험이 있다. P06은 방송알림이 이미 있어 새 문제의 크기 검증이 필요하다. P07은 P03의 검증 행동으로 흡수 가능하다. P08은 한달사용리뷰가 이미 있으며 P03의 근거로 활용한다. P09·10·12는 관찰보다 확장이 크다. P11은 P04와 재구매 맥락이 겹치며 장기 검증이 필요하다.

- B2 단독 제거: 기존 속성별 리뷰 요약에 AI 요약만 붙이면 변화가 작다. B1의 근거 검색 부품으로만 사용.
- A3·B3 보류: 사람을 넣는 것 자체보다 누구에게 어떤 질문을 보내고 얼마나 부담을 줄이는지 근거가 부족하다.
- A4·D3 제거: 자동 주문·설치·결제를 전제하면 고객 통제와 운영 의존성이 크며, 고객 문제보다 자동화 시연이 앞선다.
- C3 단독 보류: 재고 인식 없이 반복 배송을 하면 기존 정기구매와 큰 차이가 없다.
- C4 보류: 인터페이스보다 새로운 소분·체험 운영이 본체다.
- D4 제거: 혜택의 개인차를 다시 고객에게 검증시키면 원래 부담을 늘린다.
- D5 보류: 검증된 가격 이력이 없으면 ‘평소 가격’이나 미래 가격을 꾸며낼 위험이 있다.
- B5는 B1과 같은 문제를 푸므로 별도 최종 후보로 세지 않는다. 공포 영상·AI 캐릭터 논쟁·복불복 구매 같은 연출은 만들지 않는다. 증거에서 파생되는 실패 조건만 남긴다.

### 이 단계의 중요한 insight

1. **정보가 존재하는 것과 고객의 의문이 해소되는 것은 다르다.** 현재 필수정보에 제조국이 있어도 문의에는 같은 질문이 있었다. 정보의 당시 상태는 모르지만, 고객 질문을 검증 단위로 삼을 이유는 있다.
2. **최저 단가와 최소 낭비는 다른 목적함수다.** 100봉과 60봉이 이미 존재한다. 새 소포장을 만드는 것만이 해결책은 아니다.
3. **추천할수록 후보가 늘어나는 역설이 있다.** 결정을 끝내려는 고객에게 필요한 것은 다음 상품이 아니라 마지막 미확인 조건일 수 있다.
4. **상품을 덜 팔 수 있는 답이 신뢰의 장면이 될 수 있다.** ‘이미 가진 냄비로 가능합니다’, ‘기한 확인 전에는 보류하세요’가 허용돼야 고객 편의 Agent가 된다. 재방문·반품 감소 효과는 아직 가설이다.
5. **2030다운 말투보다 새로운 생활을 처음 준비하는 상황이 더 구체적인 출발점이다.** 연령별 선호 통계나 사용성 차이를 이번 탐색으로 증명하지 않았다.

### 최종 1 — 사지마 검증소

**고객 문제**

구매 후보를 정한 고객은 결제 직전에 자신의 필수 조건이 충족되는지 확인하기 어렵다. 결정에 필요한 사실이 상품 설명·필수정보·문의·리뷰에 흩어져 있거나 확인되지 않기 때문이다.

**Insight**

더 많은 칭찬과 평균 별점이 마지막 불안을 해소하지는 않는다. 고객에게 필요한 결과는 ‘추천합니다’보다 ‘당신의 탈락 조건을 확인했고, 이 항목은 아직 모릅니다’일 수 있다. 실제 냄비의 원산지 문의와 현재 필수정보를 대조한 경험이 출발점이다(S4). 기존 속성별 리뷰 요약을 다시 만드는 것이 아니라 사실 검증의 상태를 관리한다.

**Big Idea**

사고 싶은 상품과 포기할 수 없는 조건을 주면, Agent가 먼저 사지 말아야 할 이유를 조사해 **확인됨·부적합·미확인**으로 결정을 돕는 구매 전 검증 서비스.

**Magic Moment**

‘국내 제조가 필수’라는 조건을 넣자 높은 별점과 무관하게 제조국 근거를 제시하며 후보에서 제외한다. 다른 후보의 핵심 정보가 없으면 억지로 추천하지 않고 ‘이 질문 하나의 답이 필요합니다’와 문의 초안을 보여준다. 국내 제조는 데모용 개인 조건이며 제조국으로 품질을 단정하지 않는다.

**Agent**

고객의 조건을 검증 질문으로 분해 → 상품·판매자·모델을 식별 → 필수정보·판매자 답변·리뷰에서 관련 근거 검색 → 사실과 주관적 경험을 구분 → 상충·누락 감지 → 판정과 근거 링크 제공 → 미확인 항목의 판매자 문의 초안 생성. 단순 찬반 역할극이나 요약 챗봇으로 끝내지 않는다. 실제 문의 전송·답변 대기는 MVP에서 제외한다.

**Why GS**

GS SHOP은 상품과 판매자 정보, 문의 답변, 사용 리뷰, 반품 안내를 상품 단위로 연결할 수 있다. 이들은 이번 탐색에서도 확인한 자산이다. 방송의 시연 구간 연결은 향후 확장이고, 영상·자막 접근은 확보된 것으로 전제하지 않는다. 다른 쇼핑몰도 모방 가능하므로 독점성 대신 자사 근거를 추적할 수 있는 실행 이점으로 설명한다.

**Demo — 3분**

0:00~0:30 후보 상품과 필수 조건 2개 입력 → 0:30~1:20 서로 다른 자료에서 근거 카드 생성 → 1:20~2:00 평점이 높아도 조건 불일치로 제외 → 2:00~2:40 다른 후보의 정보 누락을 ‘미확인’으로 표시하고 문의 초안 생성 → 2:40~3:00 사용자가 근거 원문을 열어 확인.

**criterion 적용**

- 목표: 후보는 골랐지만 확인 부담 때문에 멈춘 고객이 자신의 필수 조건 충족 여부와 남은 질문을 파악한다.
- 완료 상태: 주방용품 5개와 사전 확보한 상품·문의·리뷰 자료를 대상으로, 조건 입력·근거 검색·3상태 판정·문의 초안·원문 이동이 작동하는 웹앱. Agent는 실제로 근거 검색과 분류를 수행한다. 정적인 결과 화면만 있으면 완료가 아니다.
- 완료 확인 기준: 사람이 정답을 표시한 10개 사례(확인 가능 4, 명시적 불일치 3, 자료 누락·충돌 3)를 실행한다. 필수 조건 불일치 3건은 모두 부적합, 누락·충돌 3건은 모두 미확인으로 처리하고, 사실 판정마다 올바른 근거 위치가 있어야 한다. 취향 리뷰만으로 공식 규격을 확정하면 실패다. 이는 향후 합격 기준이며 현재 테스트를 수행한 결과가 아니다.
- 제약: 실제 구매·자동 문의·성능 보증·자동 환불 없음. 자료의 상품 모델과 수집일을 표시한다. 원문이 없거나 상충하면 확인 필요로 남긴다. ‘미확인’은 상품 결함 판정이 아니다. 현재 상품정보와 과거 리뷰의 시점 차이를 드러낸다.

**가장 먼저 검증할 것**

후보를 이미 고른 2030 고객 5명에게 각자의 필수 조건을 말하게 하고, 기존 상세와 검증 결과에서 결정 근거를 찾게 한다. 소요 시간, 정확한 근거를 찾은 수, 남은 질문 수를 비교한다. 참가자 4명 이상이 근거를 더 쉽게 찾고 잘못된 확신이 늘지 않는 것을 초기 진행 기준으로 제안한다. 효과는 아직 검증되지 않았다.

### 최종 2 — 다먹고샵

**고객 문제**

소비가 느린 1~2인 가구는 대용량 식품을 고를 때 저렴한 단가와 실제로 다 먹을 수 있는 양 사이에서 결정하기 어렵다. 판매 구성은 수량 단위지만 생활은 소비속도와 남은 보관기간으로 움직이기 때문이다.

**Insight**

100봉과 60봉은 이미 판매되고 있다(S1·S5·S6). 문제는 구성의 부재보다 내 소비속도로 번역하는 과정일 수 있다. 리뷰의 ‘기간이 넉넉하다’는 집계도 현재 배송품의 기한이나 나의 소비 완료를 보장하지 않는다. 가장 싼 한 봉을 고르는 것과 실제 낭비를 줄이는 것은 다르다.

**Big Idea**

먹는 사람 수·일주일 소비량·현재 재고로 소비 달력을 먼저 만들고, 다 먹을 수 있는 구매 구성을 역으로 찾는 쇼핑 서비스.

**Magic Moment**

‘혼자 주 5봉’을 넣자 100봉은 20주, 60봉은 12주라는 달력이 나온다. 데모에서 확인된 사용 가능 기간을 12주로 설정하면 100봉은 40봉이 남을 수 있다고 보여주며, 더 비싼 단가의 60봉을 제안한다. ‘싸니까 더 사세요’의 방향을 뒤집는다. 12주는 가상 데모 입력이며 실제 해당 상품의 소비기한이 아니다.

**Agent**

상품별 포장 단위·수량·보관조건·확인된 기한 정보를 정규화 → 다른 구성이 실질적으로 비교 가능한지 확인 → 고객 소비속도와 재고에 적용 → 달력·예상 잔여량·총지출·불확실성 설명 → 부족한 기한 정보가 있으면 확인 질문을 만든다. 산술은 결정론적 계산 모듈로 수행하며 AI가 숫자를 추측하지 않는다.

**Why GS**

대용량과 다른 구성의 상품, 실제 소비 방식이 담긴 리뷰가 함께 있다. 방송의 ‘많이 드리는 구성’을 각 가구의 적정량으로 해석하는 접점이다. 다만 출고 로트별 기한 데이터는 이번에 확보하지 못했다. 서비스 연결 가능성을 내부에서 확인해야 한다.

**Demo — 3분**

0:00~0:30 100봉·60봉 구성 비교 → 0:30~1:00 혼자·주 5봉 입력 → 1:00~1:40 소비 완료 달력과 남을 양 표시 → 1:40~2:10 가상 기한 12주에서 작은 구성 제안 → 2:10~2:40 두 사람이 함께 먹는 조건으로 바꾸면 결과 변경 → 2:40~3:00 기한을 지우자 ‘적정량 확정 불가’와 확인 필요 표시.

**criterion 적용**

- 목표: 소규모 가구가 단가뿐 아니라 총지출·예상 소비 완료·잔여량을 보고 구매 수량을 고른다.
- 완료 상태: 동일 식품의 2~3개 구성을 비교하고 인원·소비량·재고·확인된 기한을 바꿔 결과를 즉시 갱신하는 웹앱. 기한이 없을 때의 미확인 흐름과 상품 원문 링크를 포함한다.
- 완료 확인 기준: 재고 0, 주 5봉, 사용 가능 12주라는 명시적 가정에서 100봉은 20주·잔여 40봉, 60봉은 12주·잔여 0봉으로 계산한다. 관찰 시 판매가 기준 단가는 각각 1,090원·1,150원, 총지출 차이는 40,000원이다. 60봉 구매가 총지출은 낮아도 수령량 또한 다르므로 차액 전부를 ‘절약’이라고 부르지 않는다. 두 명이 각 주 5봉이면 100봉 소비는 10주로 바뀌어야 한다. 소비량 0, 기한 미입력, 기한 경과, 기존 재고 입력도 처리해야 한다. 이들은 향후 검증 사례다.
- 제약: 리뷰에서 현재 출고품의 기한을 추론하지 않는다. 미개봉·개봉 후 보관조건을 구별하며 보관 안전성이나 영양 효과를 보증하지 않는다. 데모 기한은 가상 데이터로 표시한다. 자동 주문·소분 판매·건강 권장 섭취량 제안은 하지 않는다. 실제 가격 비교 전 구성·중량·혜택 조건을 확인한다.

**가장 먼저 검증할 것**

최근 대용량 식품을 산 1~2인 가구 5명에게 실제 소비속도를 회상하게 하고 기존 가격표와 달력을 비교한다. 적정 구성 판단 정확도, 입력할 수 있는 소비량의 신뢰도, 잔여량 예측의 유용성을 확인한다. 실제 낭비 감소는 구매 후 장기 측정이 필요하며 해커톤 클릭 지표로 대체하지 않는다.

### 최종 3 — 안 사도 되는 장바구니

**고객 문제**

첫 독립을 준비하는 생활용품 초보는 원하는 생활을 위해 무엇을 추가로 사야 하는지 정하기 어렵다. 필요한 도구와 이미 가진 물건의 대체 가능성을 스스로 판단해야 하기 때문이다.

**Insight**

‘자취 냄비’를 검색하면 상품은 나오지만 초보자의 준비가 끝나지는 않는다(S2·S3). 검색 전에 결정해야 할 것은 냄비의 브랜드보다 해먹을 음식, 열원, 보유 도구일 수 있다. 새 상품을 추천하기 전에 기존 물건으로 가능한 일을 확인하면, 준비 범위 자체를 줄일 수 있다.

**Big Idea**

하고 싶은 일과 이미 가진 물건을 입력하면, 구매할 필요 없는 품목을 먼저 지우고 부족한 것만 남기는 생활 준비 Agent.

**Magic Moment**

가상의 ‘첫 자취 준비 목록’에는 여러 조리도구가 있지만, 전자레인지와 적합한 용기를 이미 보유했다고 입력하자 준비하려는 일부 메뉴의 추가 구매가 사라진다. ‘총 몇 개 추천’ 대신 ‘이 일은 지금 가진 것으로 가능, 이 한 가지는 확인 필요’가 나온다. 실제 호환성은 제품 정보로 확인하며, 보유 여부만으로 사용 가능하다고 단정하지 않는다.

**Agent**

목표를 작업으로 분해 → 필요한 기능·열원·규격을 도출 → 보유품이 충족하는 기능과 미확인 조건 대조 → 중복·불필요 구매 제거 → 남은 기능을 만족하는 최소 후보 구성 → 각 구매의 필요 이유와 제외 이유 설명. ‘상품 추천’ 전에 ‘추가 구매가 필요한가’를 실제로 판단한다.

**Why GS**

조리도구·식품·생활용품을 가로지르는 상품군과 사용 정보가 있다. 개별 상품 전환만이 아니라 독립생활 준비의 접점으로 확장할 수 있다. 방송 콘텐츠 활용은 추가 데이터 확보 이후의 선택 사항이다. 일반 LLM의 준비물 목록과 구별하려면 실제 판매 상품의 조건 및 사용자가 가진 물건에 근거해야 한다.

**Demo — 3분**

0:00~0:30 가상 목표 ‘평일 아침과 간단한 저녁 준비’ 선택 → 0:30~1:00 열원·보유품 입력 → 1:00~1:40 불필요한 구매 항목이 지워짐 → 1:40~2:10 꼭 필요한 기능과 최소 후보 표시 → 2:10~2:40 보유품 하나를 추가하면 추가 구매가 다시 감소 → 2:40~3:00 규격 미확인 항목은 질문으로 남고 준비 체크리스트 저장.

**criterion 적용**

- 목표: 첫 독립 고객이 이미 가진 물건을 활용해 한 가지 생활 과업을 과잉 구매 없이 준비한다.
- 완료 상태: ‘간단한 자취 식사’ 한 영역, 사전 검토한 과업 3개·상품 10개 안에서 목표·열원·보유품 입력, 필요 기능 도출, 구매 제외, 부족품 추천, 근거·체크리스트 저장이 작동하는 웹앱.
- 완료 확인 기준: 동일 과업에 대해 보유품 없음·일부 보유·충분 보유의 세 입력을 실행한다. 각각 부족 기능이 반영되고, 충족된 기능 때문에 같은 역할의 구매가 강제되지 않아야 한다. 충분 보유한 검증 사례에서는 ‘추가 구매 0개’가 가능해야 한다. 호환성 불일치 상품은 제외하고, 규격 미확인 상품은 적합으로 확정하지 않는다. 사람이 작성한 과업별 필요 기능표와 결과를 대조한다. 모두 향후 구현 합격 기준이다.
- 제약: 집 전체·모든 요리로 확장하지 않는다. 사진 한 장으로 규격을 확정하거나 보유품을 자동 인식한다고 가정하지 않는다. 건강·조리 안전성을 추정하지 않고 사전 검토된 사용 조건 안에서 시연한다. 자동 구매·설치·재고 연동은 제외한다. 충분히 보유했다면 판매할 상품이 없어도 성공으로 처리한다.

**가장 먼저 검증할 것**

독립 준비 중이거나 최근 독립한 고객 5명에게 실제 준비 목록과 보유품을 받아, 빠뜨린 필수품·불필요한 추가품·완료 시간·질문 부담을 관찰한다. 사용자에게 긴 보유품 조사를 시키는 비용이 절감 효과보다 크면 이 방향은 수정한다. 세 후보 중 실제 고객 행동 근거가 상대적으로 약하므로 가장 먼저 인터뷰로 반증해봐야 한다.

## 최종 선택을 위한 판단과 남은 검증

우선 탐색 추천은 **사지마 검증소**다. 이번에 직접 확인한 고객 문의와 자료 대조 경험에 가장 가깝고, 미확인·불일치를 보여주는 순간이 분명하다. **다먹고샵**은 GS의 대용량 구성과 잘 연결되고 계산으로 시연을 검증하기 쉽다. **안 사도 되는 장바구니**는 흐름을 가장 크게 뒤집지만 보유품 입력 부담과 실제 준비 과업을 먼저 검증해야 한다.

공통 성공 지표를 클릭률 하나로 잡지 않는다. 조건을 충족하지 않는 구매를 보류하거나, 작은 구성을 선택하거나, 아예 구매하지 않는 것이 이 제품들의 고객 성공일 수 있다. 사업적 효과는 신뢰·재방문·반품·낭비 감소를 별도로 관찰해야 하며 현재 수치로 주장할 근거는 없다.

선행 G:Scene은 최종 답으로 채택하지 않았다. 상황 입력은 일부 후보에서 사용하지만 결과는 장면별 상품 진열이 아니라 검증된 판단·소비 계획·최소 준비다. 향후 고객 실험에서 상황형 발견이 더 큰 문제라는 근거가 나오면 다시 비교할 수 있다.

### 저장 전 일관성 점검

- 실제 탐색: 홈·카테고리·검색·상세·문의·리뷰·구매 전 팝업을 확인했다.
- 발산: 관찰 18개 → 서로 다른 문제 가설 12개 → 문제 4개 → 해결 방향 20개 → 중복·효용 필터 → 최종 평가 후 후보 3개.
- 최종 후보마다 고객 문제·Insight·Big Idea·Magic Moment·Agent·Why GS·Demo, 목표·완료 상태·완료 확인 기준·제약을 기입했다.
- 고객 연령·이탈·전환·반품 원인·추천 성능은 측정하지 않았다. 출시 기능 부재를 사이트 전체에 일반화하지 않았다.
- 실제 리뷰는 요약했고 작성자 식별자는 저장하지 않았다. 가격·리뷰·문의는 표본 관찰이며 대표 통계가 아니다.
- 문서 작성 완료와 제품 검증 완료를 구별했다. 제안한 테스트와 인터뷰는 아직 실행하지 않았다.
