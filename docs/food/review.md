# 식품 시나리오 개편 검증 기록

2026-09-21 · `feat/food-kitchen`. 아래 개편 기록이 현재 구현의 검증 결과다. 하단 첫 MVP 기록의 인분·용량·포장·옵션 및 비타민 빈 추천은 당시 동작이며 이번 개편에서 제거/대체했다.

## 자동 검증

- `npm test` 통과: 기존 홈 이동·입력·가구·상품·API 검사, Food 직접 이동 회귀 검사, 식품 도메인/API 15개 검사.
- `npm run typecheck`, 최종 `npm run build` 통과.
- `node tests/release-smoke.mjs` 통과: 홈/식품 페이지·API, 원천 필드/제외 필드, 로컬 주방·상품·시나리오 그림 17종과 홈 자산.
- 도메인 검사에서 9개 상품×6개 주제, 미등록 상품, 분류 매칭, 분류/상품명 충돌과 일반 백업을 확인했다. 상품/주제 조합 때문에 결과가 비지 않는다.
- 원천 9컬럼만으로 표시 매핑이 가능하며 `packSize`, `unit`, `optionLabel`, `available`, `amountPerServing` 등의 필드가 계약에 없음을 확인했다.

| 이미지·콘솔 | 표시 이미지 정상 로딩, 관찰한 console error/warn 없음 |

## 검토·수정·재검증

1. 모바일 재구매가 추천 앞에 나와 결과가 밀리는 문제를 수정하고 구매 컬렉션→추천→재구매 순서를 확인했다.
2. 장바구니 재추천 CTA가 이전 조건을 유지하는 문제, 재구매 후 상품 출처를 장바구니로 잘못 설명하는 문제를 수정하고 위 경로로 재검증했다.
3. 전체 보기 모달 닫기 시 body로 포커스가 빠지는 문제를 시작 버튼으로 명시 복귀하도록 수정해 최종 빌드에서 확인했다. 공통 font 축약 규칙이 브랜드/버튼 글꼴을 덮는 문제도 font-family 상속으로 좁혀 모바일 화면에서 확인했다.

추천은 로컬 데모 규칙이며 실제 GS SHOP 상품 추출·이미지·계정·서버 장바구니·판매 재고·주문/결제 연결은 검증하지 않았다. 물리 모바일, 스크린리더 전체 적합성, 네트워크 실패 주입도 수행하지 않았다. 일반 백업과 새 SKU 분류는 도메인 테스트에서 검증했으며 브라우저에서 임의 카탈로그를 주입하지 않았다.

# 첫 식품 MVP 검증 기록 — 이전 구현

2026-09-21 · 브랜치 `feat/food-kitchen`

기존 홈을 유지하면서 식품 페이지를 연결했다. 실제 외부 상품·주문 연동 없이 저장소의 데모 데이터와 브라우저 저장소로 수행한 검증이다.

## 자동 검증

| 검사 | 결과 |
| --- | --- |
| `npm test` | 통과. 기존 경로 탐색·입력·가구 동작·상품 표시, 홈 API 2개, 홈↔식품 연결, 식품 도메인/API 11개 검사 포함 |
| `npm run typecheck` | 통과 |
| `npm run build` | 통과. 마지막 pointer 드래그·보유 버튼 접근성 수정 이후에도 프로덕션 빌드와 TypeScript 검사 통과 |
| `node tests/release-smoke.mjs` | 홈·식품 페이지, 두 API, 홈 상품 9종, 식품에서 사용하는 고유 상품·메뉴 이미지 12개와 기존 모듈 응답 확인 |

설치와 로컬 서버 실행에는 환경의 네트워크·localhost 권한이 필요했다. 저장소 잠금 파일대로 의존성을 설치했으며 런타임 의존성이나 잠금 파일을 변경하지 않았다.

## 브라우저에서 확인한 시나리오

Codex 브라우저에서 실행 중인 프로덕션 서버 `http://127.0.0.1:3000`을 확인했다. 390×844 모바일, 320×740 작은 모바일, 1280×900 데스크톱 viewport를 사용했다.

| 시나리오 | 관찰한 결과 |
| --- | --- |
| 홈과 같은 구매 기록 | 우유·생수·멀티비타민 3종이 선반에 표시되고 우유 구매 기록에 근거한 크림 파스타가 표시됨 |
| 첫 방문 | 기록 없이 토마토 파스타를 바로 선택하고 재료 확인으로 진입 |
| 관심 저장과 새로고침 | 관심 메뉴를 저장해도 장바구니는 0개. 이후 담은 상품과 저장 메뉴 수가 새로고침 후에도 유지됨 |
| 인분 계산 | 토마토 파스타 1인분 11,200원, 4인분 18,600원. 각각 포장 수량 3개·5개 |
| 이력 없는 보유품 | 첫 방문 프로필에서 파스타를 보유로 표시하자 구매 목록에서 제외되고 7,400원·2개로 변경 |
| 담기 완료와 중복 방지 | 토마토소스와 버섯을 추가한 뒤 신규 추가가 0원·0개로 변경되고 장바구니 확인 행동 제공 |
| 과거 구매와 현재 보유 구분 | 파스타 구매 프로필에서 구매일은 표시되지만 보유는 자동 확인되지 않고 구매 후보에 포함 |
| 브라우저 뒤로가기 | 토마토 파스타에서 버섯을 보유로 표시 → 주방에서 다른 메뉴 탐색 → 브라우저 Back. 토마토 파스타가 복원되고 보유 확인이 초기화되어 다른 필요량에 잘못 적용되지 않음 |
| 모든 재료 보유 | 신규 상품이 0개가 되며 조리 순서 보기를 눌러 메뉴의 조리 단계를 펼침 |
| 기존 장바구니 부족분 | 토마토소스 1개가 이미 있는 프로필에서 4인분 추가금액은 14,100원. 추가 후 소스 2개·파스타 1개·버섯 2개, 총 18,600원이며 SKU 중복 행 없음 |
| 메뉴 없는 상품·재구매 | 멀티비타민에 레시피를 꾸며 연결하지 않고 빈 추천을 표시. 옵션 보기에서 30정·18,900원을 확인하고 장바구니에 1개 추가 |
| 드래그 탐색·저장 | 최종 빌드에서 카드 왼쪽 드래그로 크림→토마토 메뉴 전환, 오른쪽 드래그로 현재 메뉴 저장, 저장 목록에 토마토 메뉴 표시 |
| 냉장고 진입·복귀 | 기존 냉장고 열기·상품 목록이 동작하고 내 주방으로 연결됨. 복귀 전후 캐릭터 좌표 x=262/y=197 및 방향 up 일치 |
| 팬트리 진입 | 기존 상품 모달 안의 내 주방으로 링크에서 식품 화면 정상 진입 |
| 작은 화면 | 320px 장바구니 화면의 documentWidth=320 확인, 이미지 로딩 정상, 가로 넘침 없음 |
| 화면·콘솔 | 모바일 주방·재료·장바구니·홈 트레이와 데스크톱 주방을 시각 검토. 관찰한 콘솔 error/warn 없음 |

## 검토 후 수정과 재검증

1. 보유·인분 변경 메시지가 sticky 담기 버튼을 덮을 수 있어 재료 화면에서는 합계 영역 위로 이동시키고, 4.5초 후 종료 및 닫기를 추가했다. 모바일 재료 화면에서 버튼과 안내가 겹치지 않는 것을 확인했다.
2. 브라우저 뒤로가기에서 다른 메뉴의 보유·수량 초안이 재사용될 수 있어 URL에 메뉴 ID를 포함하고 메뉴 재진입 시 보유·수량·선택 재료를 초기화했다. 위 Back 시나리오로 재검증했다.
3. 터치 전용 이벤트를 pointer 기반으로 바꾸고 이미지 기본 드래그를 막아 마우스와 터치가 같은 동작을 사용하게 했다. 최종 빌드에서 좌우 드래그·저장 목록을 확인했다. 보유 버튼의 접근성 이름에도 재료명을 포함했다.

## 검증 범위와 남은 연결

실제 GS SHOP 가격·재고·추천 API, 로그인, 주문, 배송, 결제는 검증 대상이 아니다. 식품 API 네트워크 실패의 로딩·재시도 경로는 구현했지만 이번 브라우저 검사에서 실패를 강제로 주입하지 않았다. 물리적 모바일 기기의 터치 제스처와 스크린리더 전체 적합성 검사는 수행하지 않았다.

장바구니는 브라우저의 로컬 데모이며 여러 기기·탭 간 실시간 동기화와 서버 트랜잭션을 제공하지 않는다. 저장한 데이터에 따라 프로필별 탐색 상태가 유지되며, 홈의 데모 초기화로 시작 상태로 돌아간다. 실제 연동 시 `DemoFood` 계약, 보유 확인 지속 기간, 옵션·가격 검증, 서버 담기 성공·실패 계약을 먼저 합의해야 한다.
