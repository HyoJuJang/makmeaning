# 식품 MVP 구현 범위

2026-09-21 · 사용자 요청에 따라 메인 홈 다음 단계로 식품 페이지를 확장한다. 기존 AGENTS.md의 첫 vertical slice 제한은 이번 식품 기능 요청에 대해 확장된다. 기존 방 구현과 홈 API 계약은 유지한다.

## 구현할 흐름

- 홈 냉장고·팬트리에서 `/food`로 진입하고 방으로 복귀한다.
- 작은 구매·장바구니 선반, 상품 선택 및 해제, 상품 기반 또는 일반 메뉴 추천.
- 다른 메뉴, 관심 저장·해제, 되돌리기, 저장 메뉴 재진입. 스와이프는 버튼과 같은 결과를 낸다.
- 인분 1~4, 메뉴별 보유 확인, 레시피 필요량과 판매 포장 단위, 구매 선택과 추가 금액.
- 기존 장바구니 수량을 제외한 부족분만 추가하고 동일 상품 수량을 합산한다.
- 현재 판매 옵션 확인 후 재구매, 로컬 데모 장바구니 보기·수량 변경·삭제.
- 홈과 같은 구매 기록, 첫 방문, 파스타 구매, 장바구니만 있는 시연 상태를 구분한다.
- 데이터 로딩·조회 오류·재시도, 추천 없는 상품, 0개 선택, 담기 완료, 뒤로가기 처리.

## 이번 구현의 선택

기존 Next.js·React·TypeScript를 사용하고 식품 데이터는 별도 `/api/demo/food` 계약으로 제공한다. 추천은 레시피와 상품의 연결에 따른 데모 규칙이며 실제 개인화 모델을 뜻하지 않는다. 장바구니·관심 메뉴·탐색 상태는 브라우저에 저장하고 실제 구매나 외부 API 변경은 수행하지 않는다.

홈 프로필은 기존 홈의 구매 기록을 가져온다. 식품의 별도 파스타 시연 프로필은 홈의 구매내역을 변경하지 않는다. 구매 당시 수량과 홈의 사용하기 시뮬레이션은 식품의 현재 보유 확인으로 가져오지 않는다.

UX 검토 중 보유 버튼과 구매 체크박스 분리, 모든 재료의 보유 확인, 빈 선반 축소, 저장 후 현재 메뉴 유지, 저장 메뉴·장바구니 재진입을 구현 선택으로 적용한다. 최종 서비스 정책의 확정을 의미하지 않으며 교체 가능한 UI·데이터 경계로 둔다.

보유 확인은 현재 메뉴에 필요한 양을 사용자가 확인하는 기능이며 메뉴를 새로 열거나 새로고침하면 초기화한다. 관심 저장은 상품 추가를 실행하지 않는다. 판매 단위와 현재 예시 가격을 표시하며 배송비는 상품금액에 포함하지 않는다. 레시피별 필수·선택 재료를 구분하고 선택 재료는 기본 구매에서 제외한다.

## 검증할 기준

첫 방문 메뉴→재료→담기, 과거 구매 상품 선택→보유 확인→부족분 담기, 장바구니 중복 방지, 인분별 포장 수량과 합계, 관심 저장·복원, 재구매, 0개 상태, API 오류 복구를 확인한다. 기존 홈 동작 테스트와 production build·HTTP smoke, 모바일/데스크톱 브라우저 검토를 실행하고 발견한 문제를 수정 후 다시 검증한다.

실제 GS SHOP API·주문·결제·배송·추천 모델과 뷰티 상세는 이번 구현에 포함하지 않는다. 검증 결과는 `docs/food/review.md`에 기록한다.
