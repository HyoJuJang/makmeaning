# 식품 MVP 구현 범위

2026-09-21 · `feat/food-kitchen`. 사용자 후속 요청에 따라 홈의 Food 즉시 진입, 패션·생활 화면과 같은 구매/장바구니 표현, 실제 추출 컬럼 제약, 상품별 시나리오를 반영했다. 기존 메인 홈과 홈 API 계약은 유지한다.

## 화면과 진입

냉장고의 Food 영역은 `/food` native 링크이며 캐릭터 이동이나 트레이 열기를 기다리지 않는다. 팬트리·홈 하단의 기존 식품 링크도 유지한다. 홈 복귀 위치·방향·스크롤을 저장한다.

`origin/feat/fashion-living-scenes`의 `04956ac`에서 구매 컬렉션 디자인을 참고해 식품에 이식했다. 공간 그림과 구매 번호, 밑줄 탭, 가로 상품 카드, 선택 체크, 새롭게 둘러보기, 전체 보기 모달, 색상·간격·둥근 모서리를 맞췄다. 해당 브랜치 전체를 병합하거나 패션·생활 기능을 가져오지는 않았다. 주방 그림은 같은 색상의 로컬 SVG다. 데스크톱은 구매/재구매와 추천 두 열, 모바일은 구매 컬렉션→추천→재구매 순서다.

## 상품 데이터 계약

원천 `CatalogProduct`는 사용자가 약속한 다음 9개 컬럼만 사용한다. 원문의 컬럼 이름을 그대로 유지했다.

`prd_id`, `view_name`, `price`, `cate1_nm`, `cate2_nm`, `cate3_nm`, `cate4_m`, `brd_mn`, `domain`.

`adaptFoodProducts`는 화면용 `id`, `name`, `shortName`, `imageUrl`을 별도로 만든다. 이미지와 짧은 이름은 로컬 표시 정보이며 추출 데이터의 필수 필드가 아니다. 등록되지 않은 상품은 분류 그림 또는 중립 상품 그림을 사용한다. 구매일은 별도의 데모 구매 사건이며 상품 원천 컬럼이 아니다.

용량·g/ml/L·사이즈·포장 옵션·판매 가능 여부를 원천에서 임의 생성하지 않는다. 인분, 재료 필요량, 포장 수량 및 부족량 자동 계산을 제거했다. 상품의 수량은 사용자가 장바구니에 담으려고 고른 개수만 뜻한다. 가격×직접 선택한 수량으로 추가 상품금액을 계산한다.

## 핵심 시나리오

| 장면 | 직접 연결 상품 | 다음 행동 |
| --- | --- | --- |
| 토마토 버섯 파스타 | 파스타면·토마토소스·버섯 | 함께할 상품 선택 또는 조리 단계 |
| 버섯 달걀 덮밥 | 즉석밥·버섯·달걀 | 함께할 상품 선택 또는 조리 단계 |
| 우유 버섯 크림 파스타 | 파스타면·우유·버섯 | 함께할 상품 선택 또는 조리 단계 |
| 간단한 아침 준비 | 우유·달걀 | 아침 상품 선택 또는 준비 방법 |
| 일상 식품 챙기기 | 멀티비타민, 선택 상품인 생수 | 구매 목록 정리·재구매 |
| 외출 전 챙기기 | 생수 | 가져갈 식품 확인·구매 목록 정리 |

멀티비타민을 요리 재료로 취급하거나 효능·복용량·복용 시간을 추천하지 않는다. 상품별 직접 연결→분류 연결→일반 추천 순서로 후보를 확보한다. 명시적 상품과 주제가 함께 맞지 않으면 상품 관련 장면을 유지하고 조건을 완화한 이유를 보여준다. 분류 매칭은 구체 카테고리를 상품명의 단어보다 우선한다. 직접 관련이 없는 일반 제안은 그 사실을 설명한다.

상품을 선택하지 않은 추천은 장바구니·저장·구매 기록을 실제로 사용한 만큼만 설명한다. 처음 방문해도 일반 시나리오를 바로 볼 수 있다. 저장은 장바구니 추가와 별개다. 좌우 드래그와 버튼으로 다른 장면·저장·되돌리기를 제공한다.

## 상품 확인과 상태

- `집에 있어요`는 이번 장면의 구매 제외 선택이며 구매 기록에서 자동 설정하지 않는다. 새 장면·재진입·새로고침에서 초기화한다.
- 기존 장바구니 상품은 기본 추가 대상에서 빠진다. 이미 있는 개수가 충분한지 계산하지 않으며 수량 변경은 장바구니에서 직접 한다.
- 새 상품은 기본 1개이며 사용자가 변경한다. 선택 상품은 기본 체크하지 않는다. 동일 상품은 한 행으로 합산하고 최대 99개로 제한한다.
- 모두 구매 제외, 모두 장바구니에 존재, 모두 구매 체크 해제는 각각 준비 방법·장바구니 확인·선택 안내로 구분한다.
- `#products/<scenarioId>`로 장면을 복원하며 예전 `#ingredients/<id>`도 읽는다. 다른 장면의 구매 제외·수량 초안을 재사용하지 않는다.
- `gscene-food-v1` 키의 내부 버전은 2다. 이전 버전의 `recipeId`, 저장 목록과 장바구니를 복구하고 인분 정보는 버린다. 홈 초기화가 같은 키를 지운다.
- 전체 보기 모달은 native dialog이며 닫을 때 시작 버튼으로 포커스를 돌린다.

## 연동 경계

`/api/demo/food`는 가상 상품·시나리오·프로필을 반환한다. 실제 상품 수집, 개인화 모델, 로그인, 판매 옵션·재고 조회, 서버 장바구니, 주문·결제·배송은 연결하지 않았다. 현 계약에 없는 사이즈·용량 데이터를 화면 동작의 전제로 요구하지 않는다. 실제 이미지 제공 방식·구매 이력 API·장바구니 API는 이후 합의 대상이다.

검증 결과는 `docs/food/review.md`에 기록한다.
