2026-09-21 · `feat/food-kitchen`. 최신 요청은 시나리오 제거, 참조 브랜치의 움직이는 캐릭터와 UI 재사용, 동일한 뷰티 화면 추가다. 실제 브랜치 병합은 사용자가 나중에 진행하며 이번 작업에는 포함하지 않는다. 이전 메뉴/시나리오 명세를 아래 내용으로 대체한다.

## 화면 구조

`/food` 내 주방, `/beauty` 내 화장대는 `CatalogScenePage`를 공유한다. 홈의 Food/Beauty 링크는 이동 애니메이션을 기다리지 않고 바로 열린다. 구매 기록 → 공간 번호 → 구매/장바구니 탭 → 상품 선택 → 상품 상세·찜·담기 순서다. 공간 구매 상품을 선택하면 실제 캐릭터가 해당 위치로 걷고, 제자리로 버튼은 처음 위치로 되돌린다. 장바구니 상품 선택은 현재 보유나 배치를 의미하지 않는다.

`origin/feat/fashion-living-scenes`의 `5602026`에서 공통 CSS, RoomAvatar, 이동 로직과 관련 타입·테스트를 변경 없이 재사용했다. 색·서체·탭·가로 컬렉션·구매 번호·선택 체크·모달은 공통 스타일을 사용한다. 주방/화장대 배경만 별도 3:1 픽셀 SVG다. 데스크톱도 공간 → 목록의 같은 세로 구조다. 세부 통합 지침은 `../catalog/merge-preparation.md`를 참조한다.

## 데이터와 상태

원천 상품은 `prd_id`, `view_name`, `price`, `cate1_nm`, `cate2_nm`, `cate3_nm`, `cate4_m`, `brd_mn`, `domain` 9개 컬럼이다. `id`, `name`, `shortName`, `imageUrl`은 표시 어댑터에서 생성하며 실제 추출 계약에 추가하지 않는다. 크기·용량·판매 옵션·인분·재료 필요량을 만들지 않는다. 구매일은 별도 구매 사건이다.

두 API는 홈의 사용자·아바타·카테고리별 구매 기록을 재사용한다. 식품은 상품 9개/구매 3개, 뷰티는 상품 4개/구매 2개인 데모다. 그림·가격은 예시이며 뷰티의 추가 상품은 기존 로컬 그림을 재사용한다.

장바구니 수량은 사용자가 담는 상품 개수(1~99)다. 같은 상품을 다시 담는 버튼은 장바구니를 열고 자동 증가시키지 않는다. 수량 변경과 삭제는 장바구니에서 한다. 합계는 가격×수량이며 실제 주문은 없다.

상태 키는 `gscene-catalog-food-v1`, `gscene-catalog-beauty-v1`, 내부 버전 1이다. 카테고리별 장바구니와 상품 찜만 저장한다. 유효한 새 상태가 우선한다. 새 상태가 없거나 손상되었을 때 식품의 이전 `gscene-food-v1` 버전 1/2 홈 장바구니만 복구한다. 과거 장면 저장·프로필·탐색 조건은 이어받지 않는다. 알 수 없는 상품·잘못된 수량은 제외한다. 저장 불가 시 방문 중에는 계속 사용할 수 있다. 홈 데모 초기화가 세 키를 지운다.

## 제거와 후속 작업

식품의 시나리오·레시피·조리 단계·시나리오 저장·스와이프·사용자 프로필 전환·로컬 추천/백업 규칙을 코드·API·전용 이미지에서 제거했다. 추천 영역에는 준비 안내만 있고 실제 추천 상품은 생성하지 않는다. 멀티비타민도 일반 상품 상세로 열리므로 빈 한 끼 결과가 없다.

이후 확정할 사항은 추천 API의 입력/응답, 실제 상품 이미지와 구매/장바구니 연동, 통합 화면의 전역 메뉴다. 현재 데이터에 없는 용량·옵션은 구현 전제에 포함하지 않는다. 기존 메인 홈의 별도 Scene 진입 프로토타입은 이 식품·뷰티 개편 범위 밖이다.
