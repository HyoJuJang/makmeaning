# G:Scene Main Screen — 구현 명세

## 실행 계약 연결: API 기반 구매 공간 (2026-09-21)

이번 배포에서는 `docs/EXECUTION.md`를 실행 계약으로 사용한다. 기존 원룸 배경, 이동, object interaction, 캐릭터 선택과 Scene 입구를 보존하고 `GET /api/demo/home`의 사용자·구매 상품으로 초기화한다. 초기 화면은 구매 데이터를 가져오는 상태를 표시하고, 실패/잘못된 응답에서는 재시도 버튼을 제공한다. 데이터가 준비되기 전에는 공간 조작을 활성화하지 않는다.

상품 위치는 `roomSlot`으로 고정한다: `wardrobe-1/2`는 옷장 안, `fridge-1/2`는 냉장고 선반, `pantry-1`은 팬트리, `sofa-1`은 소파 쿠션, `lamp-1`은 거실 스탠드, `vanity-1/2`는 화장대 위다. API의 상품명·구매일·이미지는 물건 목록에서 사용하고, 공간 안에는 같은 실루엣의 상품을 표시한다. 가격은 목록의 보조 정보로만 제공한다. 네 카테고리와 예시 구매 데이터 표시는 유지한다.

최초 상태와 데모 초기화는 API의 `state`에서 만들어진다. 저장된 착용·잔여 수량·조명·꺼낸 화장품·캐릭터 상태는 유효한 값만 개별 복원한다. 잘못된 저장 값 하나가 전체 구매 공간을 깨뜨리지 않게 한다. 상품 이미지 파일은 `/products/{id}.svg`의 로컬 일러스트이며 실제 GS SHOP 상품 수집 결과로 표현하지 않는다.

## 기준과 범위

`AGENTS.md`, `docs/ideas/doc03_final_ideation.md`를 제품 방향의 기준으로 삼았다. `docs/ideas/ideation.png`의 첫 화면처럼 구매한 물건이 채우는 개인 공간을 구현한다. 이미지의 사실적인 3D 표현 대신 모바일에서 즉시 읽히는 정교한 2D SVG 인형의 집을 사용한다. 새로운 추천 서비스, 로그인, 구매, 장바구니, 카테고리 상세 페이지, backend는 만들지 않는다.

완료할 경험은 네 가지다: 2D 개인 공간, Fashion / Food / Living / Beauty의 명확한 위치, 구매 상품의 공간 내 실물 표현, 주요 가구를 눌러 구매 상품을 확인하고 공간 상태를 바꾸는 행동. 팝업만 열리는 목업에서 끝내지 않는다.

## 화면 구성

기준 viewport 390 × 844, 추가 검증 375 × 812와 320px 폭. 전체 페이지는 따뜻한 아이보리 바탕, 모바일 좌우 여백 20px. 데스크톱에서는 최대 520px 너비의 같은 화면을 중앙 정렬한다. 화면의 주인공인 집이 첫 화면의 절반 이상을 차지한다. 판매 가격, 할인, 추천 배너, 상품 카드 그리드는 메인에 두지 않는다.

1. 헤더: 왼쪽 짙은 녹색 `G:Scene`, 오른쪽 작은 `with GS SHOP`. 상단 여백 20px. 검색·알림처럼 미구현 버튼은 넣지 않는다.
2. 소개: 작은 `MY SCENE` 레이블, 큰 `민서의 작은 일상`(또는 `민서의 공간`) 제목, `내가 고른 물건으로 채워지는 집` 설명. 오른쪽 또는 다음 줄에 눈에 거슬리지 않는 `가상 고객 · 데모` 표기.
3. 집: 좌우 폭을 대부분 사용하는 2층 dollhouse. SVG viewBox 권장 `0 0 400 470`. 주변 식물과 옅은 그림자, 층 바닥, 외벽과 중앙 벽을 갖춘 하나의 연속된 집. 개별 방을 네 개의 일반 UI 카드처럼 그리지 않는다. 천장과 벽을 열어 내부가 보인다. 벽과 원근감 있는 얕은 바닥 면을 사용하되 WebGL은 쓰지 않는다.
4. 안내: `옷장, 냉장고, 화장대를 눌러보세요` 또는 동등한 한 줄. 각 방의 짧은 한글 이름과 영문 category는 항상 읽을 수 있어야 한다.
5. 보조 정보: `구매한 물건이 제자리에`와 실제 샘플 수량 또는 최근 구매 한 건 정도만 표시한다. 단순 장식의 가짜 navigation은 추가하지 않는다.

## 구매 데이터

가상 고객 `민서`의 구매 이력에 연결된 local data를 사용한다. 각 상품에는 id, name, category, purchasedAt, illustrationKey와 현재 상태를 둔다. 예시: 크림 니트와 블루 셔츠(Fashion), 우유·생수·멀티비타민(Food), 쿠션·스탠드(Living), 세럼·크림(Beauty). 실제 샘플 상품이 프로젝트 안에 확보되어 있으면 그 이름과 URL을 사용한다. 확인된 원본이 없으면 `예시 구매 데이터`라고 명시하고 브랜드/가격/판매 사실을 임의로 만들지 않는다. 실제 GSSHOP 수집을 완료했다고 주장하지 않는다. 이번 slice에서 검증할 것은 구매 이력과 집의 표현이 연결되는 구조다.

## interaction과 상태

네 object 모두 독립된 button이며 탭하면 선택 강조 + 아바타 이동 + bottom sheet를 연다. 방 이름 label을 누르는 것도 동일하게 작동한다. 접근 가능한 DOM button을 SVG 위에 배치하거나 SVG를 포함하는 button으로 구성하고, 클릭 영역은 최소 44 × 44px, 가능하면 가구 전체를 쓴다. 상품을 선택한 결과는 sheet가 닫힌 집에서도 유지되어야 한다.

Sheet 공통: dim backdrop, 둥근 상단 모서리, category/가구 제목(예: `내 옷장`), `구매한 물건` 소제목, 상품 silhouette + 이름 + 구매 완료 표시. `닫기` button은 항상 보이게 한다. viewport 최대 높이 75–80vh, 내부 목록만 필요 시 scroll. 미구현 추천/구매 CTA를 넣지 않는다.

- Fashion: 크림 니트/블루 셔츠 중 선택 후 `입어보기`. 착용 상품은 `입고 있어요`로 표시. 아바타 상의 색/형태가 선택 상품으로 실제 변경된다. 옷장에는 두 상품이 계속 보인다. 동일 상품 재선택은 안정적으로 동작한다.
- Food: 물/우유/영양제 수량 표시. 해당 소모품의 `하나 사용하기`를 누르면 수량이 하나 줄고 집 안의 해당 아이콘 개수 또는 잔량 표시도 줄어든다. 0에서는 `다 사용했어요`와 disabled CTA, 음수 금지. 시뮬레이션임이 분명하도록 초기 수량 3 정도로 설정할 수 있다. 시간 기반 소모는 이번 slice에서는 사용자 사용 행동으로 시연한다.
- Living: `조명 켜기`/`조명 끄기`. 램프의 따뜻한 빛과 방의 작은 glow가 실제 토글된다. 과도한 전체 화면 밝기 변화는 금지. 쿠션은 구매 목록과 방 안에 일치해서 보인다.
- Beauty: 세럼/크림의 `화장대에 꺼내두기` 또는 `사용할 물건으로 선택`. 선택한 제품이 거울 앞 가장 앞쪽에 위치하고 얇은 highlight로 구별된다. sheet 상태에 `꺼내두었어요` 표시. 이미 선택된 것을 다시 누르면 중복 생성하지 않는다.

필수 state: activeCategory|null, outfitId, foodQuantity, lampOn, featuredBeautyId, avatarRoom. localStorage로 상품 상태를 보존하는 것을 권장한다. 깨진 저장 값이나 저장 불가 환경에서도 기본값으로 실행 가능해야 한다. 재시연을 위한 `데모 초기화`는 하단에 작은 텍스트 버튼으로만 제공하고 누르면 수량과 상태를 복원한다. 주요 상태 변경은 짧은 aria-live status로 알려준다. alert()는 사용하지 않는다.

## visual direction

배경 #F7F5EE, 주 텍스트 #173F35, 보조 텍스트 #66716A, 목재 #C5A57A, 벽 #E9E3D5, sage #A8B9A0, muted blue #91A9B7. 따뜻하고 중성적인 색, 진한 녹색 point. 흰색/크림/나무/sage 중심으로 정돈한다. 작은 벽 그림, 식물, 옷걸이, 램프의 형태를 세심히 그려 입체감과 생활감을 만든다. 굵은 외곽선, pixel art, 반짝이, 점수 badge, 강한 형광색은 피한다.

시스템 한국어 sans-serif를 기본으로 하고 제목 26–30px, 본문 14–16px. 작은 영문 레이블도 최소 10–11px로 유지하고 의미 있는 정보는 12px 이상 권장. 글자 색 대비를 확보한다. sheet CTA는 짙은 녹색 바탕 밝은 글씨, 높이 48px 이상. 사용자가 누를 수 있는 가구에는 작고 일관된 category pill 또는 터치 cue를 제공한다.

## 접근성과 QA 완료 조건

키보드 Tab/Enter/Space로 네 object와 모든 action이 작동한다. aria-label에는 방과 주요 가구를 함께 적는다. sheet는 role=dialog, aria-modal, 제목 연결, 열릴 때 focus 이동, 내부 focus trap, Escape/닫기/backdrop으로 닫기, 닫힌 후 원래 object로 focus 복귀. focus outline을 숨기지 않는다. prefers-reduced-motion에서는 이동/transition을 줄이거나 제거한다.

QA는 실제 실행 URL을 mobile viewport에서 열고 다음을 직접 검증한다.

1. 390 × 844, 375 × 812, 320px 폭에서 가로 overflow와 텍스트 잘림 없이 집/4개 방을 이해할 수 있다. 첫 인상이 내 공간이며 할인 전단지나 게임 HUD처럼 보이지 않는다.
2. 첫 화면에서 각 방의 구매한 물건이 보인다. 옷장·냉장고·조명·화장대를 각각 탭하면 대응 sheet가 열린다.
3. 셔츠 착용 → 닫기 후 아바타 변경, 식품 사용 → 공간/수량 감소 및 0 하한, 조명 toggle → 실제 빛 변화, 뷰티 선택 → 전면 제품 변경을 검증한다. 재오픈에서도 상태가 일치한다.
4. 닫기, backdrop, Escape, keyboard focus, 작은 화면 내부 scroll이 정상이다. 새로고침 저장을 구현했다면 상태 복원과 초기화도 확인한다.
5. 콘솔의 치명적 에러와 runtime 실패가 없다. 실제 UI 관찰과 interaction 증거를 바탕으로 영향도가 가장 큰 문제 최대 3개만 `main_screen_review.md`에 기록한다. Builder 수정 후 해당 동작을 다시 실행하여 fix loop를 끝낸다.

## 최신 수정: 연결된 원룸과 실제 이동 (2026-09-21)

이 절은 최신 사용자 요청을 반영하며, 앞의 **2층 배치, SVG만으로 된 배경, pixel art 지양, 600ms 이내 자동 이동, 이동 전 sheet 개방** 규칙을 대체한다. 상품 data, 구매 상태, 기존 네 category 패널과 패널 내부 행동은 그대로 유지한다. 기준 이미지 `/Users/gsretail/Documents/Codex/2026-09-21/agents-md-docs-ideas-doc03-final-2/outputs/06-gather-room.png`를 직접 확인했다.

### 공간과 시각

기준처럼 높은 시점에서 내려다보는 하나의 연결된 세로 원룸으로 만든다. 별도 층·중앙 칸막이·카테고리 카드 구획은 없다. 밝은 목재 바닥, 크림 벽, 파란 직물, 창과 식물, 섬세한 pixel 일러스트 분위기를 적용한다. 배경 asset에는 UI 문구, 캐릭터, 구매 유도 배너를 넣지 않는다. 배경 위에 interactive object label, 움직이는 캐릭터, 기존 구매 상태 overlay를 놓는다. 한 장의 정적 배경만으로 기존 상품 상태 변화를 대체하지 않는다.

좌상단 옷걸이(Fashion), 우상단 열린 냉장고·팬트리(Food), 좌중단 침대, 우중단 거울·화장대(Beauty), 좌하단 소파·테이블·램프(Living), 우하단 낮은 수납장, 하단 현관. 중앙 바닥에서 현관까지 연결되는 보행 통로가 핵심이다. 캐릭터는 중앙 빈 바닥에서 시작한다. 원본 이미지의 검색·장바구니·하단 탭·추천 banner는 이번 범위에 새로 구현하지 않는다. 이미지에 보이는 UI 자체를 배경에 굽지 않는다.

### 좌표, 이동과 충돌

배경과 overlay는 동일한 논리 좌표 `400 × 600`을 공유한다. 실제 asset 비율이 다르면 비율에 맞춰 논리 높이를 정하고 아래 좌표를 비례 변환한다. object-fit으로 생기는 여백까지 고려하여 client pointer를 논리 좌표로 변환한다. resize가 현재 캐릭터 위치를 바꾸거나 클릭 위치를 어긋나게 하지 않게 한다.

캐릭터 위치는 발 중심 좌표이며 충돌 반지름은 논리 7–9px. 상체/머리는 위쪽으로 그린다. 충돌 지형은 벽과 가구의 **바닥 footprint**로 정의하며 그림의 머리 위 높이를 충돌 영역으로 쓰지 않는다. 초기 근사치는: 옷장 x25–145/y40–155, 냉장고·팬트리 x235–365/y40–175, 침대 x20–110/y175–335, 화장대 x320–373/y190–335, 소파 x20–110/y355–520, 테이블 x125–183/y385–475, 우측 수납 x325–375/y360–540. 실제 생성 배경을 확인하여 정확히 맞춘다. 화장대 stool·원형 ottoman 등 통로를 막는 실제 가구도 collider에 포함한다. 러그는 통행 가능하다. 벽 안쪽 외곽을 walkable polygon 또는 rect 집합으로 제한하고 현관 밖으로 나가지 못하게 한다.

- **WASD / 방향키:** keydown/up의 pressed-key set을 requestAnimationFrame에서 읽어 누르고 있는 동안 연속 이동한다. 이동 속도 약 95–115 논리 px/s, delta time 상한 40ms, 대각선 normalize. 축별 이동/slide 또는 작은 substep으로 반지름 충돌을 해결해 가구를 통과하지 않는다. 키 입력은 자동 경로 이동을 취소한다. keyup, blur, visibilitychange, panel open에서 pressed keys를 비워 stuck walking을 막는다.
- **Tap-to-move:** 빈 바닥 탭 위치까지 grid A* (cell 8–10px 권장) 또는 visibility graph로 실제 걸어간다. 장애물을 캐릭터 반지름만큼 확장해 path를 계산한다. 대각선은 모서리를 가로지르지 못하게 한다. 노드간 직선 smoothing은 같은 radius collision 검사를 통과한 선분에만 적용한다. 단순 직선 tween은 금지한다. 경로를 따라 같은 속도로 이동하며 새로운 탭은 기존 경로를 교체한다.
- **도달 불가:** 가구 자체 탭은 해당 object 접근 행동으로 해석한다. 의미 없는 벽/바깥 탭은 무시하거나 근처 도달 가능한 바닥까지만 이동하되 teleport하지 않는다. 경로가 없으면 `여기로는 갈 수 없어요`를 간단히 알려주고 안전한 위치에 멈춘다. 가구 내부·벽 안으로 위치를 강제 보정하지 않는다.

### object 접근 → 도착 → 패널

각 object에는 접근점(또는 후보 2–3개)과 interaction radius 16–22px를 둔다. 초기 접근점: 옷장 (155,165), 식품 (270,185), 뷰티 (305,280), 리빙 (120,350). 최종 asset/collider에 맞춰 **실제 빈 바닥**으로 조정하고 시작점에서 모두 도달 가능해야 한다.

object나 해당 label을 클릭하면 `pendingInteraction=category`를 설정하고 가장 가까운 도달 가능한 접근점까지 경로를 계산한다. 이동 중에는 패널이 열리지 않는다. 도착하고 interaction radius 안에 들어간 뒤 이동을 멈추고 해당 object를 바라보며 기존 패널을 연다. 이미 근처면 즉시 연다. 이동 중 다른 object를 누르면 목적지/예약 패널을 교체하고, 바닥 탭·키보드 이동·Escape는 예약을 취소한다. 패널을 닫으면 도착한 위치에 그대로 남는다. 자동 복귀/teleport하지 않는다. 도착 판정에 실패하면 패널을 강제로 열지 않는다.

기존 접근 가능한 object button, focus 복귀, panel focus trap을 유지한다. panel/input에 focus가 있을 때 WASD/방향키를 가로채지 않는다. 지도에 focus가 있거나 게임 영역에서 이동 중일 때만 방향키의 페이지 scroll을 막는다. 모바일은 tap-to-move로 모든 주요 기능에 도달 가능해야 한다.

### direction / walk / idle만 추가

캐릭터는 up/down/left/right의 4방향을 가진다. 대각선에서는 마지막 주축이나 큰 이동 축으로 방향을 정해 매 frame 깜박이지 않게 한다. 실제 위치가 움직일 때만 2–4 frame의 절제된 walk cycle(약 6–8fps), 멈추면 마지막 방향의 idle. 앞/뒤는 머리·얼굴 표시로, 좌/우는 옆모습/반전으로 구별 가능하게 한다. 옷장 착용 state는 모든 방향 sprite의 상의 색/디테일에 반영한다. 벽에 막혀 실제 변위가 0이면 idle이다. 그림자는 발 아래 고정되고 캐릭터 이동에 따라 함께 이동한다. 새 inventory, emote, 점프, 게임 점수, NPC는 추가하지 않는다. reduced-motion에서는 걷기 frame/bob 효과를 끄되 이동·충돌·도착 interaction은 유지한다.

### 이번 변경의 실제 화면 QA

모바일에서 바닥 탭 3곳과 네 object 탭을 실행해 통로 이동, 가구 회피, 도착 후 올바른 패널을 확인한다. 데스크톱에서 WASD와 방향키를 각각 길게 눌러 연속 이동·keyup 정지·벽 충돌·대각선 속도를 확인한다. 이동 도중 목적지 변경, panel 닫힌 뒤 위치 유지, blur 후 정지, 좁은 폭 좌표 정합을 확인한다. 네 기존 상품 action과 저장은 regression 검증한다. 가장 영향 큰 문제 최대 3개만 review에 기록하고 Builder 수정 후 같은 동작을 재검증한다.

생성 asset 확인 보충: 최종 배경 `exec-e7c8e3cb-b799-48f4-b8cc-806cf663f833.png`(1024×1536)을 직접 확인했다. 400×600 좌표로 변환 시 실제 가구 footprint 근사치를 우선 적용한다: 옷장 (38,115)–(145,156), 냉장고+열린 문 (230,126)–(311,183), 팬트리 (300,123)–(359,159), 침대 (37,171)–(118,305), 침대 옆 협탁 (36,270)–(81,322), 소파 (32,315)–(118,458), 커피테이블 (133,336)–(190,417), 원형 ottoman 중심 (195,426)/반경 24, 화장대+stool (313,223)–(366,322), TV장 (314,336)–(363,445), 현관 우측 수납 (333,438)–(379,554). 옷장과 냉장고 뒤 벽까지는 통행 영역이 아니므로 중앙 바닥의 최상단은 y120 부근, 전체 바닥 좌우는 약 x33–368, 하단은 y490 이후 현관 x230–328만 열린다. 위 footprint에 radius를 추가한다. 정확한 polygon이나 보수적인 rect로 다듬되 작은 틈을 통로로 오판하지 않는다. 접근점은 Fashion (165,160), Food (220,175), Beauty (296,270), Living (124,326), 시작 발 위치 (210,275)를 우선 사용한다. 상단 일반 예시 좌표보다 이 asset 기반 좌표가 우선한다.


## 최신 수정: 캐릭터 스타일과 선택 (2026-09-21)

캐릭터는 발 중심·보행 경로·충돌 반경을 그대로 유지하고 논리 크기 40×64의 정돈된 SVG 일러스트로 개선한다. 부드러운 얼굴, 입체적인 머리, 상의 주름, 바지와 스니커즈로 작은 화면에서도 인물을 구별한다. 숏 컷 / 소프트 웨이브 / 라운드 보브 세 외형은 헤어 실루엣, 피부와 바지 팔레트가 다르며 성별로 구분하지 않는다. 기존 구매 상의는 외형 선택과 독립적으로 유지한다. 앞·뒤·좌·우와 walk/idle을 모두 지원한다.

MY SCENE 옆의 `캐릭터 바꾸기` 버튼으로 bottom sheet를 연다. 현재 캐릭터를 기본 draft로 선택하고, 3개 큰 미리보기 카드의 `aria-pressed`로 선택을 알린다. `이 캐릭터로 적용하기`를 누를 때만 저장한다. 닫기·Escape·backdrop은 draft를 버린다. 열 때 이동과 예약 object interaction을 중지하고 기존 focus trap을 유지한다. 적용/취소 후 기존 발 위치에 남으며 재접속 시 avatarId를 복원한다. 기존 저장 데이터에 avatarId가 없거나 잘못되어도 구매 상태를 버리지 않고 기본 외형으로 보완한다.

## 최신 수정: Scene 진입만 연결 (2026-09-21)

최신 사용자 요청에 따라 `AGENTS.md`의 초기 범위에서 **Scene 입구와 조건 선택**만 확장한다. `doc03_final_ideation.md`의 `오늘은 뭘 바꾸고 싶어요?`를 구현하되 상품 추천 결과·추천 backend·구매 흐름은 이번 범위에 넣지 않는다. 기존 원룸, 연속 이동/충돌, 캐릭터 선택, 구매 data, 네 object와 패널은 유지한다.

### 메인 입구

방 아래의 낮은 우선순위 컬렉션 요약 자리를 하나의 조용한 진입 button으로 대체한다. 제목 `오늘은 뭘 바꾸고 싶어요?`, 보조문구 `지금 필요한 장면을 골라보세요`, 오른쪽 작은 chevron. 왼쪽에 방의 소파·램프를 닮은 작은 SVG(장식용 aria-hidden)를 놓는다. 기존 아이보리·목재·녹색 팔레트, 옅은 따뜻한 배경, 최소 높이 76px와 넉넉한 여백으로 일기 속 작은 제안처럼 표현한다. 캐러셀·할인·badge·추천 상품 그리드·강조 광고 banner는 없다. 집의 크기와 object label을 줄여 자리를 만들지 않는다.

### 하나의 bottom sheet: 조건 선택 → 선택한 Scene 확인

입구 tap 시 기존 modal 방식으로 sheet를 연다. 열 때 진행 중 이동/pressed keys/예약 object interaction을 중지한다. 도착 지점·아바타 외형·옷·상품 상태를 바꾸지 않는다. 동시에 object/캐릭터 sheet를 열지 않는다.

1. 헤더 `어떤 장면을 바꾸고 싶어요?`, 설명 `상황과 예산을 고르면 오늘의 Scene이 정해져요.`
2. 상황 단일 선택 그룹: `오늘 저녁` / `욕실` / `침실` / `첫 출근` / `여행 준비`. 첫 진입에서는 미선택. 각 선택은 독립된 44px 이상 control이고 선택 시 녹색 border, 옅은 녹색 fill, 체크 또는 명시적 selected 상태를 함께 쓴다.
3. 예산 단일 선택 그룹: 제목 `예산은 어느 정도인가요?`, `3만원` / `5만원` / `10만원`. 첫 진입에서는 미선택. 표시값은 각각 예산 상한 30,000 / 50,000 / 100,000원으로 저장한다.
4. 즉시 갱신되는 한 줄 preview: 미선택 `상황과 예산을 골라주세요.` / 상황만 `{상황}에 쓸 예산을 골라주세요.` / 예산만 `{예산} 안에서 바꿀 장면을 골라주세요.` / 둘 다 `{예산} 안에서, {상황}을 위한 Scene`.
5. 하단 CTA `이 Scene으로 시작하기`. 두 선택이 모두 유효하기 전에는 disabled이며 disabled 이유는 preview로 읽을 수 있다. 선택이 완료되면 활성화한다. 클릭은 같은 sheet를 즉시 확인 단계로 바꾼다. 가짜 spinner, 네트워크 로딩, 추천 상품이 준비됐다는 표현은 없다.

확인 단계: 작은 레이블 `선택한 SCENE`, 제목 `{상황}을 위한 Scene`, 조건 chip `{예산} 이내`, 짧은 설명 `상황과 예산을 선택했어요. 이 조건이 다음 상품 탐색의 기준이 돼요.`를 표시한다. 아래 별도 작은 문장 `이번 데모에서는 Scene 선택까지 체험할 수 있어요.`로 현재 끝점을 분명히 한다. CTA는 `내 방으로 돌아가기`, 보조 button은 `다시 고르기`. 전자는 닫고 입구 focus를 복귀하며 후자는 선택값이 남은 조건 단계로 돌아간다. 이는 결과 추천 화면이 아니라 명시적인 선택 요약/handoff이다.

Scene 값은 별도 state(`sceneSituation`, `sceneBudget`, `sceneStep`)로 관리해 기존 state schema를 흔들지 않는다. 같은 세션에서 닫았다 다시 열면 선택값을 유지하고 조건 단계부터 보여준다. 새로고침 유지까지는 필수 범위가 아니다. sheet의 닫기/Escape/backdrop은 언제든 메인으로 복귀하고 원래 캐릭터 발 위치를 보존한다. `데모 초기화`가 기존 전체 초기화 역할이면 Scene 선택도 미선택으로 돌린다.

### 접근성·모바일 검증

기존 dialog의 제목 연결, focus trap, Escape, backdrop, focus 복귀를 재사용한다. 상황/예산은 native radio + fieldset/legend 권장(기존 방식과 맞추려면 button + aria-pressed도 가능). 선택 변경 preview는 aria-live=polite, disabled CTA는 실제 disabled 속성. 확인 단계 전환 시 새 heading에 focus를 두고, 다시 고르기는 선택 그룹으로 focus를 옮긴다. sheet 밖의 WASD/방향키 이동 handler는 멈추며 radio 키보드 탐색을 방해하지 않는다. 320px 폭에서도 선택지가 줄바꿈되고 sheet 내용만 scroll되며 닫기와 CTA에 도달 가능해야 한다.

QA는 (1) 메인 입구→무선택/상황만/예산만에서 CTA 비활성, (2) 상황·예산 조합 변경에 preview/확인 값 정확히 반영, (3) 다시 선택·닫기·재진입 및 원래 캐릭터 위치 유지, (4) keyboard와 작은 mobile sheet의 focus/scroll, (5) 기존 캐릭터 선택·이동·네 object 구매 interaction regression을 실제 화면에서 확인한다. 영향도가 가장 큰 문제 최대 3개만 기록하고 Builder 수정→다시 실행까지 완료한다.

## 메인 공간 최종 정리 — 2026-09-22

최신 사용자 요청으로 Room의 `MY SCENE` 별도 행, 영문 eyebrow와 소개 문구, 방 아래 구매 수·그림 설명 두 문장, `오늘은 뭘 바꾸고 싶어요?` 입구를 제거한다. 이 결정은 위 Scene 입구 유지 기록보다 우선한다. 로고 아래 이름과 캐릭터 변경 버튼을 한 행에 두고 조작 안내는 16px 한 줄로 유지한다. 긴 동작 안내도 이 행 높이를 늘리지 않으며 전체 내용은 기존 live status와 interaction tray에서 전달한다. 가상 구매·보유 데모 표시는 작은 footer에 남긴다. 중앙 내 공간 탭은 더 큰 집 아이콘과 녹색 면으로 구별하고, 다른 화면에서는 현재 category 표시를 별도로 유지한다. 상품·의상 그림과 데이터 및 이동/생활 interaction은 이번 변경 대상이 아니다.

## 집과 씬의 navigation 역할 — 2026-09-22

최신 요청과 category-navigation-visuals/04-dark-room-aligned.png 기준: Room에는 하단 navigation을 렌더하지 않고 nav 예약 여백도 제거한다. 첫 가구 접근/생활 동작→준비 후 같은 가구 재탭→category의 기존 계약을 유지한다. 네 category만 하단 바를 표시하며 중앙 진녹색 사각 방 아이콘은 항상 내 공간 복귀 목적지다. 현재 category만 밑줄, 동등한5열·공통40px icon slot·12px label baseline으로 정렬한다. category 헤더의 중복 복귀 링크는 제거하고 찜/장바구니는 유지한다.
