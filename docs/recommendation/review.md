## 자동 검증

- 기존 전체 `npm test`, `npm run typecheck`, production build 통과.
- 추천 JavaScript 21개(엔진/API 12개 + 메타데이터 규칙 9개), Python 전처리 9개 통과.
- 메타데이터 결과가 클릭·빈도·날짜·인기도·상품 유사도 변경에 영향을 받지 않는지 검증.
- 네 카테고리의 두 모드가 실데이터에서 각각 6개 결과를 반환하고, 이미 구매·담은 상품 제외·도메인 경계·중복 제거를 지키는지 검증.
- 실데이터 HTTP: 예시 별칭과 원본 userid 직접 조회 결과 일치, 신규 사용자 백업, 400 입력 검증, no-store 응답, 비공개 파일 URL 404 확인.
- 기존 DB 미설정 HTTP 계약 검사 통과. 기존 홈·식품·뷰티 API는 의도된 503, Scene API 및 페이지·자산은 기존 계약 유지.
- 추천 API의 production 파일 추적에서 원본 CSV·사용자 인덱스 포함 0개 확인.

## 직접 화면 검수

기존 3000 서버와 충돌을 피하기 위해 별도 production 서버 3001에서 검사했다.

- 1280px와 390px 비교 화면: 네 도메인 전환, 두 결과 나란히 보기, 단독 결과 보기, 실제 상품명·가격·근거 표시 확인.
- 390px에서 document 너비와 scrollWidth가 모두 390px로 가로 넘침 없음.
- 추천 방식 적용 → 새로고침 → 설정 유지 확인.
- 카테고리를 빠르게 바꿔도 이전 응답이 현재 카테고리 결과를 덮어쓰지 않음.
- 존재하지 않는 사용자: 본 추천은 인기도, 메타데이터 백업은 분류별 기본 목록으로 표시. 근거 없음 안내와 기준 상품 0개 확인.
- 뷰티 화면에서 저장된 백업 적용, 본 추천으로 즉시 전환, 비교 화면 복귀 확인. 공통 DB 미설정으로 공간은 기존 오류를 표시하지만 독립 추천 패널은 정상 동작.
- 비교 페이지에서 콘솔 오류·경고 없음. 검증용 사용자 설정은 지우고 본 추천 기본값·뷰티 예시 비교 상태로 복원함.

기존 공간의 DB 연결 성공 상태, 물리 모바일 기기, 실제 로그인·주문·전환 성능은 이번 검수 범위에 포함되지 않는다.

## 검토 후 수정과 재확인

1. 다른 userid를 비교할 때 방의 데모 구매·담기뿐 아니라 선택 상품까지 제외해 서로 다른 사용자 문맥이 섞이지 않도록 수정했다.
2. 여러 출처가 섞인 결과와 백업 이유를 실제 결과 출처에 맞춰 표시했다. 인기도가 없는 경우 인기도 추천이라고 표시하지 않는다.
3. Next 파일 추적이 로컬 원본·사용자 인덱스를 포함하지 않도록 런타임 경로와 배포 제외 설정을 수정했다.

수정 후 전체 테스트·타입·빌드와 실제 HTTP, 모바일 전환을 재검증했다. 현재 가중치와 36개 연결 규칙은 사용자의 결과 비교·조정을 위한 초기값이다.
